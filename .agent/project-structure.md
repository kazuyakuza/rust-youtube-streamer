# Project Structure

# Folders in src/

- app/ - application orchestration: CLI parsing and dispatch, startup pipeline, logging initialization, error boundaries, the `demo` mode, the production `run` mode, the frame pipeline, and the interactive `auth` mode
  - `cli.rs` - std-library CLI parser: `auth` | `demo` | `run` | `--config <path>` (before/after the command) | `--help`; `DEFAULT_CONFIG_PATH` constant
  - `cli_tests.rs` - parser unit tests (18 cases: valid/invalid forms, default path, demo/auth/run usage text incl. the implemented-run line and the no-longer-claims-not-implemented guard)
  - `error.rs` - `StartupError { Usage, Configuration, LogInit }` with exit-code mapping (2/1/1) and Display contracts
  - `logging.rs` - tracing-subscriber init seam: `RUST_LOG` honored, default filter `info`, invalid value → one stderr warning + default
  - `mod.rs` - startup funnel: parse → init logging → load+validate config → dispatch (auth/demo/run); 3 whitelisted-field info events; `report_failure` single stderr line; the exit-code contract paragraph names the run-origin fatal failures in the exit-1 class (the exit-3 placeholder class was deleted with `modes.rs`)
  - `run/` - the production `run` mode (Phase-05 Task 3 + run-diagnostics Task 1 + Phase-06 Task 3 chat wiring; 28 files: 12 sources + 4 fixtures + 12 test rosters; the `modes.rs` placeholder is deleted)
    - `mod.rs` - `run_command(app_config) -> u8` exit funnel (clean stop 0 + `RUN_STOP_MESSAGE`, pre-streaming WaitCancelled 0 + `RUN_STARTUP_STOP_MESSAGE`, any fatal one `error:` line + 1), `run_outcome` (concrete-seam production startup), `install_stop_pair` (the app's single Ctrl+C handler flips the frame-loop `StopFlag`, the `WaitCanceller` AND the chat-worker stop flag), `run_runtime` (the injected-seams orchestration: credential service → scope gate → transport factory → broadcast preparation → the ONE destination reveal → gate spawn → streaming runner; the Phase-06 stage 7.5 chat-worker plan rides the gate spawn so the worker starts ONLY after `streamStatus == active`), and the module docs carrying the D-T3-6 rule-8 resource-fate policy (never delete/transition; `enableAutoStop` auto-completes; startup failures leave `ready` resources)
    - `seams.rs` - the testability parameter objects (`RunStops`, `ServiceStops`, `RuntimeStart`, `TransportFactory` returning the Phase-06 `BroadcastTransports` bundle (the chat-capable transport pair shared with the gate), `BroadcastTransport` = `Arc<dyn LiveApiTransport + Send + Sync>`; the compiler confirmed the concrete ureq transport satisfies `Send + Sync` directly, no Mutex wrapper)
    - `error.rs` - `RunError` (9 variants: Interrupt, ClientConfig, EndpointInit, Credential, InsufficientScope, Broadcast, Pipeline, GateThreadStopped, the Phase-06 `ChatRetrieval`) with helper-split Display, `is_stop_request_cancellation`, and the exit mapping (WaitCancelled 0; every other variant 1)
    - `credentials.rs` - `read_client_config` (private duplicate of `auth/flow.rs`'s helper), `establish_credentials` (client file first, then the concrete Phase-04 stops as `ProductionCredentials`), `authorize_from_service` (the service consumed verbatim), `authorize_scope_evidence` (the run-side REQUIRED_SCOPE gate before any resource creation)
    - `broadcast.rs` - `StageRuntime` param object + `prepare_broadcast` (one preparer call: O1→O2→O3→readiness→destination) + `epoch_seconds_now` (pre-epoch fallback 0 → typed `InvalidMetadata`) + the pure `public_watch_url` builder and the `WATCH_URL_PREFIX` constant (the single runtime definition of the non-secret watch-URL text; the broadcast id doubles as the video id per the recorded Phase-05 Task-1 research)
    - `gate.rs` - `SpawnedGate`: the O4-only post-start confirmation wait on a dedicated std thread (owned `Arc` transport clone + cloned flags; the `'static` spawn requirement), `GateFinish { Confirmed, Cancelled, Fatal, Panicked }`, `finish` = join then read the shared `Mutex<GateState>`; a fatal records AND flips the frame-loop stop flag, and the fatal arm first consumes the run-diagnostics Task 1 timeout diagnostics through `log_last_stream_status_on_timeout`; the confirmation wait runs behind the cfg-split `confirmation_budget_wait` (production: the D-T2-9 24 × 5 s budget byte-exact; test builds: ONE attempt at ZERO seconds via the crate-root `#[cfg(test)]` polling seam — the gate zero-sleep test rule); on confirmation success the thread emits the `WATCH_LINK_MESSAGE` info event carrying the owned non-secret `watch_url` copy; the D-T3-12 voided ready→live-log note lives here; the diagnostics constants/helpers live in the `#[path]`-mapped `gate_diagnostics.rs` sibling (two message constants + the raw-label reader re-exported `#[cfg(test)]` for the pinned tests); the Phase-06 stage-7.5 chat duty: on `GateFinish::Confirmed` the thread spawns the chat worker from `GatePlan::chat_worker` and records its join handle, and `finish` joins the confirmation thread FIRST, then the recorded chat worker (the bounded join)
    - `gate_diagnostics.rs` - the run-diagnostics Task 1 gate sibling (included by `#[path]`): the `READINESS_TIMEOUT_STREAM_STATUS_MESSAGE` / `READINESS_TIMEOUT_STATUS_UNAVAILABLE_MESSAGE` constants, the `is_confirmation_timeout` named predicate, `log_last_stream_status` (the ONE tolerated final `lookup_stream` — every outcome consumed as an info-level FACT, never fatal, never a `RunError` variant), and `observed_status_label` reading the raw documented `status.streamStatus` (never via `StreamStatusKind`, so an unknown label is still logged)
    - `streaming.rs` - the `StreamingRunner` seam (`&self` for dyn-compatibility), `StreamingExecution` bundle (redacting-`Debug` destination, no url accessor; `stream_id` and `watch_url` ride along as non-secret operator diagnostics for recorded-test capture), the production `PreparedStreaming` (start stream → the paced chat-backed loop fed by the Phase-06 `StreamingExecution.source` field, which owns the worker-fed `ChatSource` → shutdown-evidence logging → cancel-before-join on pipeline fatal → the pure `primary_shutdown_outcome` selector where `GateFinish::Fatal` outranks the pipeline error), and the run-diagnostics Task 1 evidence surface: the `FFMPEG_CLEAN_EXIT_MESSAGE` / `FFMPEG_EXIT_FAILURE_MESSAGE` / `FFMPEG_NO_DIAGNOSTICS_NOTE` constants with the helpers `log_stream_shutdown_evidence` (info on the `StreamExit` carrier / warn on the `ExitFailure` payload — emitted right after `pipeline.run()`, BEFORE the cancel check and the gate join, so the evidence survives the gate-outranking path), the private `log_clean_stream_exit`/`log_failed_stream_exit` emitters, `diagnostics_text` (empty tail → `none captured`) and the `#[cfg(test)]` `stream_exit_failed` predicate; the selector signature, the shutdown order and the single-`error:`-line contract stay byte-stable
    - `source.rs` - `ChatSource`: the Phase-06 worker-fed `MessageSource` — owns the bounded-channel receiver plus the shared terminal-error cell and stop flag; `next_message` drains NON-blocking (`try_recv`), consults the terminal cell on `Disconnected`, and yields `Ok(None)` while the channel is open and empty (the frame loop never blocks on chat); replaces the Phase-05 `ChatFreeSource`
    - `chat_failure.rs` - the closed transient class (`is_transient_chat_failure` naming Network/5xx/BackendUnavailable/MalformedResponse/`rateLimitExceeded`) and the three-way terminal mapping into the typed retrieval errors (ChatUnavailable / Quota / Transport, redacted details only)
    - `chat_worker.rs` - the bounded chat worker: the fixed-capacity `sync_channel` (`CHAT_CHANNEL_CAPACITY = 64`), the stage-7.5 plan/constructor consumed by `run_runtime` (3-arg sanctioned exception), the D-12/D-13 constants (dedup window 512, default poll interval 10 s, 1 s sleep slices, 60 s backoff cap, 10-failure transient budget, 6 × 5 s chat-id-resolution budget), the shared `StopFlag` and terminal cell; spawn happens at `GateFinish::Confirmed`
    - `chat_worker_delivery.rs` - the poll cycle: baseline discard of the entire first successful page, the server-interval honor loop (`pollingIntervalMillis`, bounded default), the stop-aware `try_send` delivery (≤ 64 queued, never blocking shutdown), the stop-sliced sleeps, and the capped doubling backoff
    - `runtime_test_fixtures.rs` / `runtime_credential_fakes.rs` / `runtime_runner_fixture.rs` / `runtime_chat_fakes.rs` - the offline doubles (`#[cfg(test)]`): the Mutex-based scripted `LiveApiTransport` + serde_json resource builders, the credential-side fakes (`FakeStore`/`FakeEndpoint`/`FakeVerifier`) + minimal parsed client config, the recorded streaming-runner fake, and the chat-side scripted `LiveChatTransport` + canned chat pages (never real-shaped, never reaching Google)
    - `*_tests.rs` - 51 unit tests (mod_tests 4 message/exit-constant + watch-link line/URL + gate-timeout status-message pins, error_tests 5 incl. the primary-selector matrix and the chat-retrieval exit mapping, credentials_tests 3, gate_tests 7 — the 3 prior zero-sleep outcomes + the 4 run-diagnostics tests: exactly-one-extra-final-lookup ledger, tolerated failing final lookup, no extra lookup on non-timeout fatals, raw-label reader —, runtime_tests 5 incl. the §5 operation ledger and the shutdown-order proof, streaming_diagnostics_tests 3 pinned evidence-line constants + pure-helper classification, streaming_stage_tests 1 unix process test capturing the production FFmpeg argv (audio-token + derived CBR asserts), plus the Phase-06 chat rosters: chat_source_tests 5, chat_worker_tests 6, chat_worker_flow_tests 4, chat_worker_budget_tests 6, gate_chat_tests 2)
  - `auth/` - the real interactive OAuth `auth` mode (9 files: 4 sources + 5 test files)
    - `mod.rs` - `run_auth(config) -> u8`: builds the transport/store seams, runs the flow; `AuthError` (10 variants: client file, client config, listener bind, callback abandoned, state mismatch, provider declined, token exchange, persistence, insufficient scope, missing refresh token) with hand-written Display contracts; every variant maps to exit 1 (the startup-failure class); redaction contract (no token/secret/code ever reaches a log field or error line)
    - `flow.rs` - the ordered flow: read+parse the configured OAuth client file first, bind the loopback listener, open authorization (URL print + callback wait), exchange the code, validate the granted scope and refresh token offline, persist via the injected store, print the success line; test-visible seam `run_with_listener`; the listener drops deterministically on success AND failure
    - `listener.rs` - loopback callback listener: binds `127.0.0.1` on an ephemeral port only, bounded noise budget, CSRF state validation, typed HTTP responses; `BoundListener` closes the socket when dropped
    - `console.rs` - plain-stdout brochure prints (authorization URL instructions, success line); deliberately NOT tracing events
    - `mod_tests.rs` / `flow_tests.rs` / `flow_exchange_tests.rs` / `listener_tests.rs` / `console_tests.rs` - 25 unit tests (mod_tests 4 + flow_tests 7 + flow_exchange_tests 4 + listener_tests 8 + console_tests 2)
  - `demo/` - local-only demonstration mode (6 files): predefined messages at deterministic intervals through the shared pipeline (never contacts YouTube)
    - `mod.rs` - `run_demo(config) -> u8`: installs the single Ctrl+C handler first, runs the shared pipeline against `OutputKind::Demo`, prints `demo recording finalized: <path>` only after verified finalization; `DemoError { Interrupt, Pipeline }` both map to exit 1 (the startup-failure class; `demo` never exits 3)
    - `schedule.rs` - fixed timeline: 28 messages (`DEMO_MESSAGE_TOTAL`), 30-frame black lead-in, at most one message per 15 frames, 60-frame tail (final frame index 495 → 496 rendered frames ≈ 16.5 s at 30 FPS); ids `demo-NN` hidden from screen; long-line message index 15; exceeds the example 26-line visible capacity so FIFO eviction is exercised
    - `source.rs` - `DemoMessageSource`: at most one scheduled message per call, stop requested at the final frame
    - `mod_tests.rs` / `schedule_tests.rs` / `source_tests.rs` - 14 unit tests (exit mapping, capacity/eviction schedule facts, clock-free source behaviour)
  - `pipeline/` - application-level frame pipeline: chat → renderer → streaming (17 files: 8 sources + 7 test files + `test_helpers.rs` + `source_helpers.rs`)
    - `mod.rs` - `FramePipeline`, the `prepared_pipeline`/`prepared_stream_pipeline` construction seams (`PipelineConstruction`/`StreamParts`), re-exports (`StopFlag`, error types, both installer entry points)
    - `clock.rs` / `pacing.rs` - monotonic frame clock and FPS-paced schedule (backlog dropped to one immediate frame; `interval_nanos` exact division)
    - `runner.rs` - the frame loop: continuous frames at configured FPS, at most one new message per frame, complete-frame writes with short-write/broken-pipe propagation, ordered sink finalization; `run` returns the target-aware `CompletedOutput`
    - `interrupt.rs` - `StopFlag` (`Arc<AtomicBool>` clone-shared), the app's single `ctrlc` handler install (demo), and the generic `install_stop_request_handler(Box<dyn Fn() + Send>)` used by `run`; the 6 documented shutdown limitations live in its module docs
    - `error.rs` - frame-size guards and typed `FramePipelineError` (chat stage, rendering, output)
    - `source.rs` / `source_error.rs` / `test_helpers.rs` - the chat-source seam, WIDENED by Phase-06 D-8: `MessageSource::next_message` now returns `Result<Option<ChatMessage>, ChatSourceError>` where `ChatSourceError { Chat(ChatError), Retrieval(ChatRetrievalError) }` (the three-way typed retrieval class: ChatUnavailable / Quota / Transport, redacted details), plus shared pipeline test doubles
    - `*_tests.rs` - unit tests at every seam (exact byte counts, empty first frames, rotation/eviction, stop-before-start/after-Nth-write, error mapping; Phase-06 additions: `source_error_tests` 3 Display/source pins, `runner_retrieval_tests` 1 retrieval-to-`ChatRetrieval` mapping pin, and the pipeline `error_tests` gained the `ChatRetrieval` Display/source pin → 3)
