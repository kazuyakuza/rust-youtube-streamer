# Project Structure

# Folders in src/

- app/ - application orchestration: CLI parsing and dispatch, startup pipeline, logging initialization, error boundaries, the `demo` mode, the production `run` mode, the frame pipeline, and the interactive `auth` mode
  - `cli.rs` - std-library CLI parser: `auth` | `demo` | `run` | `--config <path>` (before/after the command) | `--help`; `DEFAULT_CONFIG_PATH` constant
  - `cli_tests.rs` - parser unit tests (18 cases: valid/invalid forms, default path, demo/auth/run usage text incl. the implemented-run line and the no-longer-claims-not-implemented guard)
  - `error.rs` - `StartupError { Usage, Configuration, LogInit }` with exit-code mapping (2/1/1) and Display contracts
  - `logging.rs` - tracing-subscriber init seam: `RUST_LOG` honored, default filter `info`, invalid value → one stderr warning + default
  - `mod.rs` - startup funnel: parse → init logging → load+validate config → dispatch (auth/demo/run); 3 whitelisted-field info events; `report_failure` single stderr line; the exit-code contract paragraph names the run-origin fatal failures in the exit-1 class (the exit-3 placeholder class was deleted with `modes.rs`)
  - `run/` - the production `run` mode (Phase-05 Task 3; 17 files: 9 sources + 8 test/fixture files; the `modes.rs` placeholder is deleted)
    - `mod.rs` - `run_command(app_config) -> u8` exit funnel (clean stop 0 + `RUN_STOP_MESSAGE`, pre-streaming WaitCancelled 0 + `RUN_STARTUP_STOP_MESSAGE`, any fatal one `error:` line + 1), `run_outcome` (concrete-seam production startup), `install_stop_pair` (the app's single Ctrl+C handler flips BOTH the frame-loop `StopFlag` and a `WaitCanceller`), `run_runtime` (the injected-seams orchestration: credential service → scope gate → transport factory → broadcast preparation → the ONE destination reveal → gate spawn → streaming runner), and the module docs carrying the D-T3-6 rule-8 resource-fate policy (never delete/transition; `enableAutoStop` auto-completes; startup failures leave `ready` resources)
    - `seams.rs` - the testability parameter objects (`RunStops`, `ServiceStops`, `RuntimeStart`, `TransportFactory`, `BroadcastTransport` = `Arc<dyn LiveApiTransport + Send + Sync>`; the compiler confirmed the concrete ureq transport satisfies `Send + Sync` directly, no Mutex wrapper)
    - `error.rs` - `RunError` (8 variants: Interrupt, ClientConfig, EndpointInit, Credential, InsufficientScope, Broadcast, Pipeline, GateThreadStopped) with helper-split Display, `is_stop_request_cancellation`, and the exit mapping (WaitCancelled 0; every other variant 1)
    - `credentials.rs` - `read_client_config` (private duplicate of `auth/flow.rs`'s helper), `establish_credentials` (client file first, then the concrete Phase-04 stops as `ProductionCredentials`), `authorize_from_service` (the service consumed verbatim), `authorize_scope_evidence` (the run-side REQUIRED_SCOPE gate before any resource creation)
    - `broadcast.rs` - `StageRuntime` param object + `prepare_broadcast` (one preparer call: O1→O2→O3→readiness→destination) + `epoch_seconds_now` (pre-epoch fallback 0 → typed `InvalidMetadata`)
    - `gate.rs` - `SpawnedGate`: the O4-only post-start confirmation wait on a dedicated std thread (owned `Arc` transport clone + cloned flags; the `'static` spawn requirement), `GateFinish { Confirmed, Cancelled, Fatal, Panicked }`, `finish` = join then read the shared `Mutex<GateState>`; a fatal records AND flips the frame-loop stop flag; the D-T3-12 voided ready→live-log note lives here
    - `streaming.rs` - the `StreamingRunner` seam (`&self` for dyn-compatibility), `StreamingExecution` bundle (redacting-`Debug` destination, no url accessor), the production `PreparedStreaming` (start stream → chat-free loop → cancel-before-join on pipeline fatal → the pure `primary_shutdown_outcome` selector where `GateFinish::Fatal` outranks the pipeline error)
    - `source.rs` - `ChatFreeSource`: the `MessageSource` that always yields `None` — the frame loop stays continuous chat-free; the `app::pipeline::source` seam is byte-unchanged for Phase 06
    - `runtime_test_fixtures.rs` / `runtime_credential_fakes.rs` / `runtime_runner_fixture.rs` - the offline doubles (`#[cfg(test)]`): the Mutex-based scripted `LiveApiTransport` + serde_json resource builders, the credential-side fakes (`FakeStore`/`FakeEndpoint`/`FakeVerifier`) + minimal parsed client config, and the recorded streaming-runner fake (never real-shaped, never reaching Google)
    - `*_tests.rs` - 17 unit tests (mod_tests 1 message/exit-constant pin, error_tests 4 incl. the primary-selector matrix, credentials_tests 3, gate_tests 3 zero-sleep outcomes, runtime_tests 5 incl. the §5 operation ledger and the shutdown-order proof, streaming_stage_tests 1 unix process test capturing the production FFmpeg argv)
  - `auth/` - the real interactive OAuth `auth` mode (9 files: 4 sources + 5 test files)
    - `mod.rs` - `run_auth(config) -> u8`: builds the transport/store seams, runs the flow; `AuthError` (10 variants: client file, client config, listener bind, callback abandoned, state mismatch, provider declined, token exchange, persistence, insufficient scope, missing refresh token) with hand-written Display contracts; every variant maps to exit 1 (the startup-failure class); redaction contract (no token/secret/code ever reaches a log field or error line)
    - `flow.rs` - the ordered flow: read+parse the configured OAuth client file first, bind the loopback listener, open authorization (URL print + callback wait), exchange the code, validate the granted scope and refresh token offline, persist via the injected store, print the success line; test-visible seam `run_with_listener`; the listener drops deterministically on success AND failure
    - `listener.rs` - loopback callback listener: binds `127.0.0.1` on an ephemeral port only, bounded noise budget, CSRF state validation, typed HTTP responses; `BoundListener` closes the socket when dropped
    - `console.rs` - plain-stdout brochure prints (authorization URL instructions, success line); deliberately NOT tracing events
    - `mod_tests.rs` / `flow_tests.rs` / `flow_exchange_tests.rs` / `listener_tests.rs` / `console_tests.rs` - 25 unit tests (mod_tests 4 + flow_tests 7 + flow_exchange_tests 4 + listener_tests 8 + console_tests 2)
  - `demo/` - local-only demonstration mode (6 files): predefined messages at deterministic intervals through the shared pipeline (never contacts YouTube)
    - `mod.rs` - `run_demo(config) -> u8`: installs the single Ctrl+C handler first, runs the shared pipeline against `OutputKind::Demo`, prints `demo recording finalized: <path>` only after verified finalization; `DemoError { Interrupt, Pipeline }` both map to exit 1 (the startup-failure class; `demo` never exits 3)
    - `schedule.rs` - fixed timeline: 28 messages (`DEMO_MESSAGE_TOTAL`), 30-frame black lead-in, at most one message per 15 frames, 60-frame tail (final frame index 495 → 496 rendered frames ≈ 16.5 s at 30 FPS); ids `demo-NN` hidden from screen; long-line message index 15; exceeds the example 26-line visible capacity so FIFO eviction is exercised
    - `source.rs` - `DemoMessageSource`: at most one scheduled message per call, stop requested at the final frame
    - `mod_tests.rs` / `schedule_tests.rs` / `source_tests.rs` - 14 unit tests (exit mapping, capacity/eviction schedule facts, clock-free source behaviour)
  - `pipeline/` - application-level frame pipeline: chat → renderer → streaming (13 files: 7 sources + 5 test files + `test_helpers.rs`)
    - `mod.rs` - `FramePipeline`, the `prepared_pipeline`/`prepared_stream_pipeline` construction seams (`PipelineConstruction`/`StreamParts`), re-exports (`StopFlag`, error types, both installer entry points)
    - `clock.rs` / `pacing.rs` - monotonic frame clock and FPS-paced schedule (backlog dropped to one immediate frame; `interval_nanos` exact division)
    - `runner.rs` - the frame loop: continuous frames at configured FPS, at most one new message per frame, complete-frame writes with short-write/broken-pipe propagation, ordered sink finalization; `run` returns the target-aware `CompletedOutput`
    - `interrupt.rs` - `StopFlag` (`Arc<AtomicBool>` clone-shared), the app's single `ctrlc` handler install (demo), and the generic `install_stop_request_handler(Box<dyn Fn() + Send>)` used by `run`; the 5 documented shutdown limitations live in its module docs
    - `error.rs` - frame-size guards and typed `FramePipelineError` (chat stage, rendering, output)
    - `source.rs` / `test_helpers.rs` - chat-source seam (BYTE-unchanged for Phase 06) and shared pipeline test doubles
    - `*_tests.rs` - unit tests at every seam (exact byte counts, empty first frames, rotation/eviction, stop-before-start/after-Nth-write, error mapping)
- config/ - loading, validation and exposure of the application configuration
  - `mod.rs` - public API: `load_from_path(&Path) -> Result<AppConfig, ConfigError>`; module docs
  - `model.rs` - strongly typed structs mirroring `config/config.example.json` (serde derive, `deny_unknown_fields`), including the `oauth` section (`client_config_path`, `credentials_path`)
  - `loader.rs` - read → parse → validate pipeline
  - `validation.rs` - 21 validation checks grouped as named predicates (5 positive dimensions/FPS/size values, exact `rgb24`, 1 vertical layout ≥ 1 line, 10 non-blank strings/paths incl. FFmpeg fields, 1 privacy enum, 2 non-blank OAuth paths + 1 OAuth path-distinctness rule)
  - `error.rs` - `ConfigError { Io, Deserialization, Validation }` + aggregated `ConfigIssue` (typed, actionable, no panics)
  - `loader_tests.rs` / `validation_tests.rs` - 21 unit tests (temp files via `tempfile`; no real developer config)
  - `test_fixtures.rs` - shared test fixture builder (`#[cfg(test)]`)
- youtube/ - YouTube API integration: OAuth 2.0 authorization, credential persistence/refresh/verification, plus the Phase-05 production-live runtime (broadcast/ingestion lifecycle; 62 files: 35 sources + 27 test files). The `src/youtube/.gitkeep` placeholder was retired when the real module landed.
  - `mod.rs` - module docs: scope authority, the fake/loopback test-seam list, and the post-wiring state: the Task-3 run wiring landed (2026-10-14), so the Phase-04 pair and all six Task-2 module-level staging allows were deleted and the production re-exports added (`LiveApiTransport`, `CredentialService`/`VerifiedCredentials`, `CredentialServiceError`, `AuthorizationVerifier`, `GoogleAuthorizationVerifier`, `GoogleLiveApiTransport`, `LiveApiError`, `LiveBroadcastPreparer`/`PreparedBroadcast`, `wait_until_stream_active`/`StreamObservationRequest`, `WaitCanceller`, `AccessToken`; plus `#[cfg(test)]`-only re-exports the offline fakes name: the five `live_models` command/resource types, `GrantedScopes`/`RefreshToken`/`RefreshRequest`/`TokenExchangeResult`/`VerificationError`/`VerifiedAuthorization`). The only module-level staging that remains is the compiler-arbitrated V2 pair (`live_models`, `live_lifecycle` — see the inventory below); the standing no-network test rule (fakes or `127.0.0.1` loopback only) holds
  - `client_config.rs` - parses the downloaded Google Desktop-app client JSON (`installed` schema, exact `auth_uri`/`token_uri` endpoints); blank/endpoint-mismatch typed errors
  - `token.rs` - redacted OAuth token material: secret wrapper types (`AccessToken`, `RefreshToken`, `AuthorizationCode`, PKCE verifier) whose `Debug` never reveals the secret and which have no `Display`; the token-endpoint response body type deserializes only (formatting a raw body is a compile error)
  - `transport.rs` - the mockable `TokenEndpointTransport` seam (authorization-code exchange + refresh) and its request shapes
  - `google_token_endpoint.rs` - the concrete `ureq`-backed token-endpoint implementation (no Tokio), HTTP-status-first error classification with redacted reasons
  - `authorization.rs` - OAuth constants: Google endpoints, `REQUIRED_SCOPE` (`https://www.googleapis.com/auth/youtube.force-ssl`), the authorization URL builder, PKCE (S256) and state generation
  - `verify.rs` - `VerifiedAuthorization` result type + the mockable verification seam (the `granted_scopes` evidence reader is consumed by the run-side permission gate)
  - `credentials.rs` - the `CredentialStore` seam (`load`/`save`) and `StoredCredentials` (access token, advisory `expires_in_seconds`, optional refresh token, granted scopes)
  - `persisted_credentials.rs` - the frozen 4-key on-disk JSON schema (`access_token`, `expires_in_seconds`, `refresh_token` nullable, `granted_scopes` space-delimited)
  - `file_credential_store.rs` - concrete `FileCredentialStore`: atomic save (temp + rename in the same directory, stale-temp cleanup), POSIX 0600 created-file mode, typed read/save failures (Windows rename/permission arms cannot be exercised in the Linux container; no encryption, documented)
  - `credential_service.rs` - the reusable credential service consumed verbatim by the production `run` startup: load stored credentials → offline gate on the persisted scope evidence → verify-first probe (no clock-based refresh) → refresh via the stored refresh token exactly once when the probe rejects the token → persist atomically → re-verify the refreshed token once
  - `credential_service_error.rs` - typed service failures (absent, unreadable, revoked, unrefreshable, insufficient scope, verification, persistence, transport), hand-written Display, redacted
  - `google_authorization_verifier.rs` - the concrete `AuthorizationVerifier`: minimal, READ-ONLY `GET /youtube/v3/channels?part=id&mine=true` with the Bearer header; 200/401/403 (+error bodies) classified status-first into typed outcomes; never performs broadcast operations
  - `live_models/` - typed serde models for the documented `liveBroadcasts`/`liveStreams` fields (unknown fields tolerated, missing parts → `None`), the transport-agnostic O1–O3 command types, the exact insert-request bodies (autoStart/autoStop, monitor stream off) and the pure config→CDN label mapping (1920×1080@30 → `1080p`/`30fps`; off-table → `variable`/`variable`), plus the two `StreamCreationCdn` label accessors; split into `mod.rs`, `broadcast_resource.rs`, `stream_resource.rs`, `stream_cdn.rs`, `commands.rs`, `request_bodies.rs` so each file stays under the 200-line cap; consumed by the Task-2 transport/orchestrator (the module carries the V2 re-staged allow for the documented fields the runtime does not read yet)
  - `live_lifecycle.rs` - `BroadcastLifecycle` (8 documented `lifeCycleStatus` labels) and `StreamStatusKind` (5 documented `streamStatus` labels); unknown labels are typed `MalformedResponse`; `is_transition_pending` (liveStarting/testStarting) and `is_streamable_setup` (ready) predicates; consumed by the readiness/confirmation waits (the module carries the V2 re-staged allow for the pending-state predicate)
  - `live_error/` - `mod.rs` holds the `LiveApiError` enum (15 variants incl. the Task-2 `WaitCancelled` typed cancellation; no secret-bearing field); `classify.rs` holds the pure status-first `classify_api_error(status, reason)` mapping of the official §1.5 table (consumed by the concrete transport); `display.rs` holds the hand-written Display split into per-variant helpers, never a panic. Split keeps each file under the 200-line cap
  - `scheduled_start_time.rs` - RFC 3339 `snippet.scheduledStartTime` derivation — `now + 60 s` (`SCHEDULED_TIME_OFFSET_SECONDS`), pure civil-from-days formatter duplicated from the sealed streaming module, saturating epoch math (no clock crate); consumed by the orchestrator
  - `api_transport.rs` - the mockable `LiveApiTransport` trait with exactly the five selected operations (create_stream, create_broadcast, bind, lookup_stream, lookup_broadcast); `lookup_*` returns `Ok(None)` only for a verifiably empty list answer; implemented by the concrete ureq backend
  - `api_request.rs` - wire plumbing of the concrete transport (Amendment-2 cap re-cut of F-T2-1): the `LiveApiRequestSpec` request-form parameter object + its three D-T2-4 constructors, the five documented path+query builders (ids percent-encoded RFC 3986), the locked request-body serialization seam, the shared 2xx body read (fixed unreadable-body text), the status-first reason-extraction path into the classifier, and the deliberate D-T2-6 local duplicate of the verifier's private `extract_reason`
  - `google_live_api_transport.rs` - the concrete `GoogleLiveApiTransport` (ureq, redirects disabled, OAuth Bearer only — never an API key): one request engine over the spec forms, ONE status-first `respond` path (ureq 2 surfaces 3xx as `Ok` with redirects(0), so the Ok arm is status-first and 3xx falls through the classifier into `ApiRejected`), five-operation `LiveApiTransport` impl; JSON posts send `send_string` + explicit `application/json` (ureq's `send_json` is feature-gated off; no dependency change); the compiler confirmed the type is `Send + Sync`, so the run runtime shares it into the gate thread via `Arc` with no wrapper
  - `live_ingestion.rs` - the orchestrator: `LiveBroadcastPreparer::from_config` (validated config → typed commands; stream title reuses the broadcast title; CDN labels via the `stream_cdn` accessors; `scheduled_start_time_from_epoch`) and `prepare` (D-T1-8 steps 3–6 exactly once each: O1 insert stream → O2 insert broadcast → O3 bind with the `boundStreamId` assertion → the bounded readiness wait → destination extraction); `PreparedBroadcast` (derived `Debug` secret-safe through the redacting wrapper) exposes `broadcast_id()`, `stream_id()` (the Task-3 addition for the post-start confirmation wait) and `into_ingestion()`
  - `readiness_wait/` - directory submodule (Amendment-2 cap re-cut): `mod.rs` (`ReadinessWait` core with the D-T2-9 typed-const budget contract 180 s / 5 s → 36 attempts + `#[cfg(test)] with_polling` re-injection + attempt-bounded `run`; re-exports `StreamObservationRequest` and `wait_until_stream_active` at `pub(crate)` for the gate), `confirmation_wait.rs` (the O4-only `wait_until_stream_active`, 120 s → 24 attempts + test re-injection, consumed by the Task-3 gate thread), `observation.rs` (`StreamObservationRequest`, the single `stream_observation`/`broadcast_observation` mappings, the transient/fatal attempt matrix: `Network`/5xx consume an attempt, all other classified errors abort)
  - `rtmps_ingestion.rs` - the redacting `RtmpsIngestion` destination wrapper: exactly `rtmpsIngestionAddress/streamName`, NO fallback to `ingestionAddress`, layered `DestinationMissing` guards, `Debug` = `RtmpsIngestion(<redacted>)`, no `Display`, `into_url` as the ONE reveal point (consumed by the run-mode reveal expression)
  - `wait_cancellation.rs` - the youtube-local `WaitCanceller` (`Arc<AtomicBool>`, `SeqCst`, the `StopFlag` shape without any `crate::app` dependency); consumed by the run-mode Ctrl+C link and both waits
  - `live_test_fixtures.rs` - `#[cfg(test)]` shared test support (the `config::test_fixtures` precedent; Amendment 1): the scripted `LiveApiTransport` fake (queued per-op results, operation-label recording, captured commands, the deterministic cancel-during-wait hook) and the canned live-resource builders; never built in production
  - `error.rs` - typed OAuth errors per boundary (client config, callback query, token endpoint), hand-written Display contracts, no secret leakage
  - `*_tests.rs` (27 siblings) - 156 unit tests: client_config 12, credentials 1, authorization 8, token 7, transport 2, google_token_endpoint 1, error 2, file_credential_store 10, persisted_credentials 5, credential_service (shared-fakes seam file 0 + refresh 9 / verification 9) 18, verifier loopback 7 + classify 4 (Phase 04 landed 72; the v0.7.1 endpoint-allowlist hotfix added 5 client-config tests → 77); Phase-05 staged design artifacts: live_models 8, live_lifecycle 7, live_error 9 + live_error_display 2 (incl. the Task-2 `WaitCancelled` appends), scheduled_start_time 4; Phase-05 Task-2 (50 new): wait_cancellation 2, readiness_wait 12 (loop 10 + confirmation 2, roster-C split), rtmps_ingestion 6, google_live_api_transport 13 (assembly 2 + outcomes 11, roster-A split), live_ingestion 15 (happy 6 + failures 9, roster-B split); and Phase-05 Task-3 (1 new): the `PreparedBroadcast` stream-id accessor test. Every network boundary is a fake or a `127.0.0.1` loopback server; no test reaches Google.
- chat/ - application-level chat message model and bounded visible-message queue (ChatStore); independent of YouTube API types, network, streaming and FFmpeg (implemented and wired into the runtime through the app frame pipeline and the `demo` mode)
  - `mod.rs` - module docs: log-append-first contract and scope authority (TODO §1); private submodule declarations (re-exports return at the first external consumer)
  - `model.rs` - `ChatMessage { author, text, message_id: Option, timestamp: Option<u64> }`; builder attachers for optional API metadata; `Display` is exactly `author: text` (metadata never visible); newline normalization flattens line breaks to one space
  - `store.rs` - `ChatStore`: `VecDeque` FIFO of visible messages, log file opened eagerly in append/create mode; `accept` appends the log record FIRST and rejects the message on I/O failure (queue and log never diverge); evicts oldest beyond capacity; `visible_text` joins `author: text` lines with `'\n'`; new stores start empty, the log is never read back
  - `error.rs` - `ChatError { Capacity, LogOpen, LogAppend }`; hand-written `Display` contracts, `std::error::Error::source`, no panics
  - `model_tests.rs` / `store_tests.rs` - 16 unit tests (display/normalization/metadata; capacity, FIFO eviction, append-only log ordering and I/O-failure semantics; temp files via `tempfile`)
- renderer/ - converts RenderInput to complete raw RGB24 frames (width * height * 3 bytes, row-major, R/G/B); independent of YouTube API types, chat state, network and FFmpeg (implemented and wired into the runtime through the app frame pipeline and the `demo` mode)
  - `mod.rs` - module docs; `#[path = "renderer.rs"] mod contract;` mapping keeps the trait out of `clippy::module_inception`
  - `renderer.rs` - `RenderInput { text }` (complete visible multiline text) and the `Renderer` trait (`render -> Result<Frame, RenderError>`); validation happens at construction, `render` fails only on frame-allocation overflow
  - `settings.rs` - `RendererSettings::from_config` (re-checks positive dimensions, vertical layout ≥ 1 line, parses `#RRGGBB` `Rgb` case-insensitively) and `Rgb` with uppercase `Display`; no file-existence check (Phase 01 precedent)
  - `frame.rs` - `Frame` with checked `width * height * 3` construction (`filled`), `blend_at` no-op outside the frame, deterministic round-half-up coverage blending
  - `text.rs` - `TextRenderer` (ab_glyph `FontVec`, font parsed once at construction, missing/unparseable fonts are typed errors, no silent fallback); line-box placement baseline = `top_margin + ascent + i * line_height`; per-pixel clipping at the physical frame boundary, horizontal cut at `x == width`, no wrapping/font resizing; unknown codepoints render as notdef, skipped with advance kept
  - `error.rs` - `RenderError { Geometry, FrameSize, Layout, InvalidColor, FontOpen, FontParse }`; hand-written `Display`, `source()`, no panics
  - `*_tests.rs` / `text_test_helpers.rs` - 19 unit tests (`#[cfg(test)]` in-tree test modules; font fixture `fonts/Exo2-Light.otf`)
- streaming/ - FFmpeg process supervision and raw-frame input pipeline (17 files: 11 sources + 6 test files), sealed boundary rules: depends only on `std` + `crate::config::model`, never on chat/renderer/YouTube types, and receives frames as opaque `&[u8]` through the `FrameSink` seam
  - `mod.rs` - module docs + boundary rules; `pub(crate)` re-exports (`StreamingError`, `FfmpegProcess`, `RtmpsDestination`, `FrameSink`/`CompletedOutput` (+ `CompletedVideo` test-only), `resolve_output_path`/`OutputKind`)
  - `args.rs` - the two pure locked argument vectors built from validated config: the local recording (`-nostdin -n -f rawvideo … -movflags +faststart <output>`, byte-unchanged) and the Phase-05 stream (`… -g <2 × fps> -pix_fmt yuv420p -f flv <destination_url>` — no faststart, explicit FLV muxer, official 2-second-target GOP); no shell, no env, no filesystem
  - `error.rs` - typed `StreamingError` (pixel-format guard, executable location, output directory/name, Spawn, FrameWrite, WaitFailed, ExitFailure with diagnostics tail, OutputFinalize); hand-written `Display`/`source()`; 4096-byte trailing diagnostics capture
  - `ffmpeg.rs` - `FfmpegProcess`: the two spawn paths over ONE engine (`start` → local MP4 with finalize check; `start_stream` → RTMPS destination with the URL recorded as the stderr-redaction target), piped stdin/stdout/stderr, no shell; `finish()` = stdin EOF → drains → exit-status check → local finalize check only when a local output exists; `Drop` kills and reaps; NO `Debug` derive (the destination inside must never become formattable)
  - `pipe_drain.rs` - the shared drain-thread machinery plus the mandated diagnostics redaction pass (the destination URL is replaced with the `REDACTED_TEXT` `[redacted]` marker — the constant lives in `ffmpeg.rs` — before any `ExitFailure` payload is built)
  - `local_finalize.rs` - the local-output finalization check (exists + non-empty, conservative probe direction); the streaming finish never runs it
  - `rtmps_destination.rs` - the streaming-owned secret wrapper (`private url`, `pub(crate) new`, `pub(super) as_url` consumed only by the `args`/`ffmpeg` siblings, `Debug` = `RtmpsDestination(<redacted>)`, no `Display`); the youtube-side `RtmpsIngestion` stays separate because neither module may depend on the other
  - `sink.rs` - `FrameSink` trait (`write_frame`/`finish`) and the target-aware `CompletedOutput { Recording(CompletedVideo), Stream }` — the only types the pipeline sees
  - `spawn.rs` - the shared no-shell spawn plumbing both starts use (the Task-3 two-args extraction): the private `SpawnPlan` parameter object (`arguments` + exactly one of `local_output`/`redaction_target`; no `Debug`/`Display` may ever be derived — `redaction_target` IS the secret), `spawn_with` (`pub(super)`), the typed missing-stdin fallback and the piped-`Command` builder
  - `video_output.rs` - `resolve_output_path`: beside-executable `videos/` directory created on demand; collision-safe `demo-` names (`_2.._1000`); conservative existence probe; `OutputKind::Demo` remains the sole variant (production writes no local file)
  - `utc_timestamp.rs` - `YYYYMMDD-HHMMSS` UTC timestamp (civil-from-days, leap handling)
  - `*_tests.rs` - unit tests incl. `ffmpeg_tests.rs` (6 fake-FFmpeg POSIX-script process tests, `#[cfg(all(test, unix))]`), `ffmpeg_stream_tests.rs` (3 streaming process tests: clean-exit `Stream` completion, `[redacted]` diagnostics, destination-free Spawn display), `rtmps_destination_tests.rs` (2), +2 locked-shape stream-vector tests in `args_tests.rs`, and `ffmpeg_real_tests.rs` (1 real-FFmpeg smoke: 64×36@5fps record + ffprobe assertions, loud image-tool prerequisite)

# Root files

- Cargo.toml - Rust package manifest: `rust-youtube-streamer-service` v0.8.0, edition 2021; deps: ab_glyph (renderer font rasterization), ctrlc (cross-platform Ctrl+C flag-flip handler for the pipeline stop seam), oauth2 5.0 with the `ureq` feature (OAuth authorization-code flow + PKCE + refresh; no Tokio), serde (derive), serde_json, tracing, tracing-subscriber (env-filter), ureq 2 (synchronous HTTP transport for the OAuth token endpoint, the authorization verifier and the YouTube Live API transport); dev-dep: tempfile
- Cargo.lock - tracked lockfile for the executable package (sole root-level generated artifact)
- src/main.rs - entry point delegating to the `app` layer (`mod app; mod chat; mod config; mod renderer; mod streaming; mod youtube;` — no `#[allow(dead_code)]` attributes; they were retired when Phase 03 wired chat/renderer into the runtime)
- Dockerfile - pinned official `rust:1.82` base; installs rustfmt/clippy components for checks, `gcc-mingw-w64-x86-64` (Windows GNU cross toolchain: fallback linker route + objdump import audit) and the `x86_64-pc-windows-gnu` Rust target for the Windows cross-build
- docker-compose.yml - `rust` service for Docker-based cargo checks; bind-mounts the project and redirects build artifacts to the `rust-streamer-target` named volume
- .gitattributes - forces LF line endings for `*.sh` and `Dockerfile` so container-executed files survive the repo host's `core.autocrlf=true` checkout behavior
