## Scope and Tasks

### 1. Inspect the Current Repository

- Inspect the current branch and working tree before changes.
- Review the existing root files, `src/` directories, configuration/documentation directories, `.gitignore`, and project structure map.
- Confirm whether any files or changes have appeared since the project-info status was last updated.
- Reuse existing directories and conventions. Do not create duplicate structures or remove project/agent configuration.

### 2. Establish the Minimal Cargo Project

- Add a root `Cargo.toml` for a single Rust executable package named consistently with the existing project, using a valid Rust crate/package name such as `rust-youtube-streamer-service`.
- Use the Rust edition appropriate for the currently installed stable toolchain and document the chosen edition. Do not add dependencies speculatively.
- Add `src/main.rs` with only the smallest idiomatic entry point needed to prove the package builds.
- Do not create empty module files for all future features merely to match the target architecture. Feature modules will be introduced by their respective phases.
- Generate and commit `Cargo.lock` as appropriate for the executable package.
- Do not implement configuration parsing, logging infrastructure, OAuth, YouTube API calls, rendering, chat handling, or FFmpeg process management in this phase.

### 3. Establish Baseline Development Checks

- Confirm the Rust toolchain and Cargo are available in the implementation environment before claiming validation.
- Run `cargo fmt --check`.
- Run `cargo check --locked` after the lockfile has been generated.
- Run `cargo test --locked`; the initial project may have no substantive tests yet, but the command must succeed.
- Run `cargo clippy --locked -- -D warnings` if the installed toolchain supports it without requiring unrelated code or dependency changes.
- If a command cannot be run, report that fact and its reason. Do not report an unexecuted command as passing.
- Do not claim Windows or Linux validation unless the commands were actually executed on those platforms.

### 4. Establish Repository Hygiene

- Review `.gitignore` and make only the additions required to keep generated Rust build output and local secrets/configuration out of version control.
- Ensure `target/` is ignored.
- Preserve the existing policy that the real `config/config.json`, OAuth credentials/tokens, stream keys, and runtime log output must not be committed.
- Do not ignore `Cargo.lock` for this executable application.
- Do not add real credentials, machine-specific paths, generated binaries, or FFmpeg binaries to the repository.

### 5. Update Documentation and Project Metadata

- Update the root README only as needed to describe the minimal build baseline and the current state; do not attempt the deferred full README rewrite.
- Add concise initial build instructions for the available toolchain, including the commands used to check and test the project.
- Keep platform claims factual: list which operating systems were actually tested, and identify other targets as intended rather than validated.
- Update `.agent/project-structure.md` so it accurately reflects the addition of `Cargo.toml`, `Cargo.lock`, and `src/main.rs`, while retaining the existing module-directory descriptions.
- Update `.agent/project-info/context.md` with the resulting repository state, actual checks performed, any limitations, and the next implementation step.
- Tests and documentation are part of this phase's acceptance criteria, not optional follow-up work.

## Platform and Runtime Constraints

- Windows and Linux are intended development/runtime targets; Ubuntu Server is the production target.
- The application will be launched directly by the user. Do not register it as a Windows service, install it as a system service, create a service wrapper, or introduce an installer.
- FFmpeg is an external prerequisite that the user installs or provides separately. Do not download, install, bundle, or configure system-wide FFmpeg as part of this phase.
- The application and FFmpeg are assumed to run under a normal user account with the required read/write permissions to the chosen files and directories. Do not add administrator-elevation behavior.
- Detailed FFmpeg prerequisite/configuration and Windows execution guidance belongs in the appropriate later documentation task, in a document linked from the README. Do not expand Phase 00 into that full guide.
