## Scope and Tasks

### 1. Create scripts/dev-checks.sh [DONE]

- New POSIX-sh compatible script `scripts/dev-checks.sh` (max ~100 lines; small helper functions; clear names).
- Behavior (all checks run sequentially in the compose container, output merged via `2>&1` per command):
  1. Ensure `logs/checks/` exists (`mkdir -p logs/checks` — permitted; inside gitignored dir).
  2. Open log file `logs/checks/<UTC timestamp>.log` (e.g. `date -u +%Y%m%dT%H%M%SZ`); write an environment header (container, cargo version, UTC timestamp) into the log AND echo it to stdout.
  3. Run checks in order, each teeing console+log, printing `== <name> == start` and a final per-command line `PASS|FAIL <name> exit=<code> (<duration>s)`:
     - `fmt-check`: `cargo fmt --check` — must NOT auto-modify source; on failure report diff and continue.
     - `check`: `cargo check --locked`
     - `test`: `cargo test --locked`
     - `clippy`: `cargo clippy --locked -- -D warnings`
  4. Summary block: one line per check (`PASS|FAIL name exit=<code>`), plus overall `ALL CHECKS PASSED|N CHECK(S) FAILED`; log file path returned on stdout.
  5. Exit code: `0` when all pass, `1` when any fails (aggregate; never swallow failures).
- Constraints:
  - NEVER writes outside `logs/checks/` (and the container-local named volume via cargo). No `target/` in the mount. No source mutation, no fmt auto-apply.
  - Keep functions ≤ 50 lines; no commented-out code; readable names; minimal comments only where logic is non-obvious.
  - Log files accumulate (append timestamps, no rotation logic) — acceptable at this scale.
  - The script is run inside the container; assume its cwd is `/rust-youtube-streamer` (compose working_dir).
- Validation via single MCP commands (vm_status first): script full run exit 0 with all PASS lines; failure-path sanity: temporarily verify a FAILING command shape prints `FAIL … exit=<n>` and yields script exit 1 (do this WITHOUT committing a broken tree — e.g., run `sh scripts/dev-checks.sh` and if any check fails, stop and report; for the failure-path sanity, an isolated `sh -c` inside container invoking a modified copy is NOT allowed (no root writes); acceptable failure-path evidence: run script with an intentionally-failing ad-hoc command stated in the implementation plan; if no clean way, document why and skip — never fake evidence).
