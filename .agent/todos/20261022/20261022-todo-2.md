## Objective

v0.9.1): (1) the previous HTTP 411 fix is CONFIRMED on real Google (bind succeeded, the stream was
created and visible in YouTube Studio) and the run now fails LATER — the post-start confirmation

(2) add an OPTIONAL per-stream made-for-kids configuration property, mapped to the documented
`status.selfDeclaredMadeForKids` field of the broadcast creation request — implemented ONLY IF the

Pre-analysis evidence (planner, 2026-10-22):

- Log timeline: `stored authorization verified` 23:17:40 → `broadcast prepared for streaming broadcast_id="xZTbF0bDRII"` 23:17:44 (O1+O2+O3 bind + readiness wait all succeeded) → `FFmpeg started toward the configured streaming destination` 23:17:44.7 → gate timeout 23:19:52 (≈120 s budget + ~8 s shutdown) → exit 1.
- Failure-shape deduction from the code: `GateFinish::Fatal` is recorded only when the gate runs to its full budget WITHOUT cancellation; a pipeline fatal would have cancelled the gate and become the reported error. So the frame loop stayed healthy the entire wait — FFmpeg was alive and consuming stdin frames while YouTube registered no ingest. FFmpeg-side instant failures (unsupported rtmps protocol, missing libx264, publish rejection) would have exited the process and surfaced as a pipeline error — ruled out by this log.
- The app captures FFmpeg stderr continuously (drain threads + 4096-byte trailing diagnostics, destination URL redaction already built) but surfaces it ONLY inside an `ExitFailure` error payload; a clean/other exit path and the gate-outranking path drop the evidence silently.
- The confirmation wait (`readiness_wait/confirmation_wait.rs`) discards the last observed `streamStatus` on timeout; whether the status stayed `ready` (YouTube never saw ingest) is the key discriminator for the next diagnostic step.
- The made-for-kids popup the operator observed in YouTube Studio (channel advanced setting "review every video") is a plausible holder of the ingest acceptance; the operator has since changed the channel default to "not made for kids", but wants per-stream control via config regardless.
- Operator follow-up (NOT agent work): this failed run created ANOTHER orphaned `ready` broadcast + liveStream pair in YouTube Studio (plus the one from the earlier 411 run); both must be deleted in Studio per `docs/production-run.md` §7 before the next attempt.

## Scope and Boundaries

- Task 1 (diagnostics) is confined to the run-mode failure/shutdown reporting path: FFmpeg's exit status and its captured, destination-redacted stderr tail must be surfaced during a run's shutdown (both the gate-timeout path and any pipeline-fatal path), and the gate must report the last observed `streamStatus` label when the confirmation wait times out (one additional tolerated O4 lookup at failure time is acceptable). The single-`error:`-line failure contract, the exit-code contract, the shutdown order, the resource-fate policy and every redaction guarantee stay byte-stable; the new diagnostics are info/warn-level log lines only, never `error:` lines, and never carry the destination URL or stream key (the existing `[redacted]` machinery applies to anything surfaced).
- Task 2 (made-for-kids config) is CONDITIONAL per the user ruling: proceed ONLY IF official documentation confirms `status.selfDeclaredMadeForKids` is settable on `liveBroadcasts.insert` AND the change is a simple optional field in the existing O2 request body plus an optional config field (no lifecycle, transport, redaction or shutdown restructuring). If the research disproves simplicity/documentedness, record-and-skip: document the finding and the reason, implement nothing, and the TODO records the skipped decision.
- No Live Chat work (Phase 06); no resilience-hardening items (they stay "candidates, not commitments"); `demo` and `auth` behavior byte-stable.
- Version: semver MINOR 0.9.1 → 0.10.0 (a new user-facing config capability rides with this TODO if Task 2 lands; if Task 2 is skipped the bump still reflects the new diagnostics surface as shipped behavior).
- Offline tests only (fakes or `127.0.0.1` loopback; never Google); the real-Google confirmation of everything remains the operator's manual E2E procedure.

## Explicitly Out of Scope

- Any change to the broadcast/stream fate policy, shutdown ordering, exit-code mapping, or the single-error-line contract beyond the diagnostics additions.
- A config option to force RTMP over RTMPS or any ingestion-endpoint fallback (the no-fallback rule stands; revisit only with evidence from the new diagnostics).
- Automating made-for-kids selection in YouTube Studio or any other non-API workaround.
- Live Chat (Phase 06); resilience hardening (bounded FFmpeg exit wait, request timeouts, watchdogs, supervisors).
