# Stop-Path Fix (Ctrl+C Reaches FFmpeg Child) + Stream-Health Bitrate Remedies (CBR video, real-bitrate audio)

## Objective

The operator's fourth native Windows `run` (`logs/run/20261025-020431.log`, v0.11.0) is the first
FULLY SUCCESSFUL live broadcast: `stream confirmed active on YouTube` + the watch link printed
~10 s after FFmpeg started; the broadcast auto-completed seconds after the operator closed the
program (enableAutoStop working as documented). Two defects remain:

1. **Stop-path bug (exit 1 on a user-initiated stop)**: FFmpeg's diagnostics (the v0.10.0 evidence
   machinery) show `Exiting normally, received signal 2` and `exit_code=Some(255)` — the console's
   Ctrl+C reached the CHILD (a bare `Command::new` in `src/streaming/spawn.rs` gives the child no
   process-group isolation; on Windows the console control event reaches every attached process;
   on POSIX SIGINT targets the foreground process group, child included). FFmpeg therefore
   self-terminates via its SIGINT path with exit 255 instead of finalizing cleanly on our stdin
   EOF, `finish()` correctly classifies the non-zero exit as `ExitFailure`, and the run reports a
   pipeline failure + exit 1 — violating the recorded contract that a clean user stop maps to
   exit 0 with the stop message.
2. **Stream-health warnings (Studio, cosmetic but operator-facing)**: "not receiving enough video
   to maintain smooth streaming" — the encoded video carries ~18.5 kbit/s against the configured
   6000k (a pure-black source cannot be padded to an ABR target; x264 sits at its QP floor:
   `Avg QP: 0.05`, ratefactor −50.21) while YouTube's own guidance recommends CBR; and "audio
   bitrate (0) lower than the recommended 128 Kbps" — the AAC encoder spends ~2 kbit/s encoding
   digital silence (`audio:54KiB` over ~195 s), so the actual bitrate is ~0.

## Scope and Boundaries

- Task 1 (stop-path fix): give the spawned FFmpeg child process-group/signal isolation so the console's Ctrl+C reaches ONLY the application (whose handler flips the stop flag; the loop ends; stdin EOF drives a clean FFmpeg finalize; exit 0 + the stop message). Platform mechanics: Windows `CREATE_NEW_PROCESS_GROUP` creation flag (std `CommandExt`); POSIX the child's own process group (`CommandExt::process_group(0)`); both behind small platform-gated helpers in the streaming module (its std+config-only boundary keeps holding). `demo` shares the same spawn path and inherits the isolation — its exit-code contract stays byte-stable (Interrupt → 1); `auth` untouched; every exit-code mapping for fatal failures unchanged.
- Task 2 (health-remedy argument changes, STREAMING vector only): (a) force true CBR video — `-maxrate`/`-minrate`/`-bufsize` derived from the configured bitrate plus the x264 `nal-hrd=cbr` filler mechanism (YouTube's own recommendation; aligns the measured bitrate with the target so the low-video warning disappears; filler data is the documented CBR mechanism); (b) real-bitrate audio — switch the silent track's codec to MP3 CBR (`libmp3lame`, `-b:a 128k`), which pads silence to the real bitrate (MP3 is an officially accepted YouTube audio codec; the AAC-on-silence ~0-bitrate shape cannot be padded). The DEMO/local-MP4 vector stays byte-stable; the config schema gains NO new fields (both remedies derive from the existing validated fields); every YouTube/OAuth/diagnostics surface byte-stable.
- Honest limits preserved: a console/window CLOSE (not Ctrl+C) still terminates both processes abruptly (documented; Drop kills/reaps our side; the broadcast auto-completes via enableAutoStop); the operator must use Ctrl+C for the graceful path.
- Version: semver PATCH 0.11.0 → 0.11.1 (both tasks fix defect-class behavior).
- Offline tests only (fakes or `127.0.0.1` loopback; the real-FFmpeg container pins use the local toolchain, never Google); real-Google confirmation stays the operator's manual E2E.

## Tasks

### 1. Stop-Path Fix — Isolate the FFmpeg Child from the Console Ctrl+C [DONE]

- In the shared spawn plumbing, isolate the child from the console's Ctrl+C: Windows spawns with `CREATE_NEW_PROCESS_GROUP`; POSIX spawns the child in its own process group — small platform-gated helpers, no new dependencies, no behavior change for any other surface.
- Pin offline (container/Linux): a fake-FFmpeg process test proving the child SURVIVES a SIGINT delivered to the parent's process group and then finalizes cleanly on stdin EOF (the incident shape reversed); Windows-side behavior is compile-checked via the cross-build + documented as container-untestable.
- After the fix, a Ctrl+C stop is expected to produce: FFmpeg exit 0 (clean finalize), the run outcome clean-stop (exit 0 + the stop message) — verify the shutdown-order tests still hold and no pinned line drifts.

### 2. Stream-Health Remedies — CBR Video + Real-Bitrate Silent Audio (streaming vector only) [DONE]

- Video CBR: derive `-maxrate`/`-minrate`/`-bufsize` from the configured bitrate (bufsize = 2× bitrate, named constant) plus the x264 `nal-hrd=cbr` filler mechanism in the streaming vector; verify with a real-container pin that the measured output bitrate reaches ≈ the configured target (ffprobe; tolerance recorded honestly).
- Audio: switch the silent track to MP3 CBR (`-c:a libmp3lame -b:a 128k`) so silence encodes at the real bitrate (documenting the libmp3lame prerequisite for operator builds; the spawn failure for a build lacking it is already a clear typed error).
- Update the pinned vectors/argv tests + the real-container audio pin; docs: the streaming-vector documentation lines + production-run.md health-warning guidance (what CBR/MP3 fix and what remains cosmetic) + context record.
